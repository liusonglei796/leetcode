25. K 个一组翻转链表：探查与递归缝合

将 Hard 难度的复杂指针拓扑，拆解为「先探后切、局部调头、递归接回」的标准心智模型。

一、直击本质：你的核心思路

核心直觉：
1. 探步数：先探 $k$ 个节点，数量不足 $k$ 直接原样返回（递归基，保留原序）；
2. 记后继：够 $k$ 个就「探完节点记住第 $k+1$ 个」；
3. 局部转：反转当前前 $k$ 个节点；
4. 递归接：把剩余部分递归处理，接回当前组尾部。

许多人在做 LeetCode 25 题时容易陷入大量指针（prev, curr, next, groupPrev, groupNext）的混乱泥潭中，极易导致成环或断链。 而递归分治法的精妙之处在于：每一层递归只专注处理当前这 $k$ 个节点的翻转，剩下的长链表交给递归子问题，最终两段自然缝合。

三、时序代码实现 (Idiomatic Go)

代码严格按照业务执行的时间先后顺序向下排列，并标注每一个阶段的入参来源与出参去向： 

// reverseKGroup: K 个一组翻转链表主入口
// 来源: 外部调用的待处理链表头节点 head 及步长 k
// 用于: 返回完整翻转并缝合后的整条链表新头节点
func reverseKGroup(head *ListNode, k int) *ListNode {
    // Step 1.1: 探查当前组是否存在完整的 k 个节点
    // 来源: 入参 head 与 k
    // 用于: Step 1.2 校验步数与寻找下一组边界
    curr := head
    for i := 0; i < k; i++ {
        // Step 1.2: 校验探查结果，不足 k 个直接原样返回
        // 来源: Step 1.1 当前探查指针状态
        // 用于: 触发递归基，保护尾部保持原序
        if curr == nil {
            return head
        }
        curr = curr.Next
    }

    // Step 2.1: 记住第 k+1 个节点（下一组的头节点）
    // 来源: Step 1.1 走满 k 步后指针停在的位置 curr
    // 用于: Step 3.1 剩余链表递归调用的起始入参
    nextGroupHead := curr

    // Step 2.2: 翻转当前组的前 k 个节点 [head, nextGroupHead)
    // 来源: 当前组头节点 head 与边界 nextGroupHead
    // 用于: 获得局部反转后的新头节点 newHead
    newHead := reverseRange(head, nextGroupHead)

    // Step 3.1: 将剩余部分递归处理
    // 来源: Step 2.1 记录的 nextGroupHead
    // 用于: Step 3.2 得到后续链表翻转后的新头节点 remainedHead
    remainedHead := reverseKGroup(nextGroupHead, k)

    // Step 3.2: 把后续递归结果接回当前组的尾部
    // 来源: 翻转后原 head 变为当前组尾节点，与 Step 3.1 返回的 remainedHead
    // 用于: 完成整条链表的指针拓扑缝合
    head.Next = remainedHead

    return newHead
}

// Step 2.2.1: 局部区间反转辅助函数 [head, stop)
// 来源: Step 2.2 传入的 head 与终止边界 stop
// 用于: 翻转指定区间内的指针方向，并返回区间新头节点
func reverseRange(head, stop *ListNode) *ListNode {
    var prev *ListNode = nil
    curr := head
    for curr != stop {
        next := curr.Next
        curr.Next = prev
        prev = curr
        curr = next
    }
    return prev
}
