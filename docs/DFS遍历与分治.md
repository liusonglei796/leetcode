# DFS 遍历（前序 / 中序 / 后序）与分治

> 一句话结论：**后序遍历是分治的通用框架。combine 处有没有产出新值，决定它只是「遍历」还是「分治」。**

---

## 1. 递归骨架：三种序就是三种遍历顺序

```
前序：solve(自己)   → solve(子)
中序：solve(左)     → solve(自己) → solve(右)
后序：solve(子)     → solve(自己)
```

同一个 DFS 函数骨架，只改「处理当前节点」这一行的位置，就得到三种序。

| 序 | 处理节点的时机 | 子问题结果用得上吗 |
|---|---|---|
| 前序 | 递归之前 | 用不上（或只用于剪枝） |
| 中序 | 左右之间 | 通常用不上（顺序由结构决定） |
| 后序 | 递归之后 | **用得上，在此处汇总** |

---

## 2. 分治四要素在后序里的位置

```
            ┌── 分解：按左右子树切开
f(node) ────┼── 求解子问题：dfs(left) / dfs(right)
            ├── 合并：在当前节点 combine(左结果, 右结果)
            └── 出口：node == nil 返回初值
```

Go 模板（背下来）：

```go
func dfs(node *TNode) Result {
    if node == nil {
        return zeroResult          // 出口：必须返回「可合并的初值」
    }
    l := dfs(node.left)            // 求解子问题：两个都要等
    r := dfs(node.right)
    return combine(l, r, node)     // 合并：唯一的分治发生地
}
```

递归栈的语义正好对上这个结构：`f(node)` 要等两个子调用都返回才继续，所以它天生是「先拿齐子结果，再合并」。

---

## 3. 纯遍历 vs 真正的分治（关键区别）

| 场景 | 合并处做了什么 | 是不是分治 |
|---|---|---|
| 纯后序遍历，把节点值收集进 slice | 只 append 到同一个答案，**不产生新值** | 退化的分治，只是借了树形框架 |
| 树形分治：543 直径 / 236 LCA / 124 最大路径和 | 用子结果**算出新值**：高度、直径、LCA 节点 | 是分治 |

```go
// 纯遍历：合并 = 收集，不产生新值
func postorder(n *TreeNode, out *[]int) {
	if n == nil {
		return
	}
	postorder(n.Left, out)
	postorder(n.Right, out)
	*out = append(*out, n.Val) // 只是收集
}

// 树形分治：合并 = 由子结果算出新值
func dfs(n *TreeNode) int {
	if n == nil {
		return 0
	}
	lh := dfs(n.Left)             // 子结果：左子树高度
	rh := dfs(n.Right)            // 子结果：右子树高度
	dia = max(dia, lh+rh)         // 合并出过根直径（全局更新）
	return max(lh, rh) + 1        // 合并出子树高度（返回值）
}
```

所以后序遍历是**分治的退化实例**：分解、求解子问题都在，唯独合并是空操作。

---

## 4. 前序：只有分解，没有合并

前序对应分治的**分解阶段 + 自顶向下传参**：

- 先处理自己，再带着自己算出的东西（上下界、剩余目标、路径前缀）递归下去
- 子问题照样被求解（递归调用发生了），只是**返回值被丢弃**，因此没有 combine

```go
// 98 验证二叉搜索树（带上下界的前序版）：约束沿树向下传
func dfs(n *TreeNode, low, high int) bool {
	if n == nil {
		return true
	}
	if n.Val <= low || n.Val >= high {
		return false
	}
	return dfs(n.Left, low, n.Val) && dfs(n.Right, n.Val, high)
}
```

前序独有的能力：**不必把子问题算完**。一旦剪枝成立就 `return`，剩余子树根本没被求解 —— 这是前序比后序更省的场景（如二叉树路径搜索、236 LCA 的提前返回）。

很多算法是**前序 + 后序混用**：前序负责剪枝 / 传上下文，后序负责汇总答案（124 二叉树中的最大路径和：前序向下累积路径和，回溯时算最大路径）。

## 5. 链表 / 数组上的对应写法

后序思想离开二叉树照样成立，「合并点」依然在递归返回处：

```go
// 23 合并 K 个升序链表：数组分治 + 合并点在 return
func mergeKLists(lists []*ListNode) *ListNode {
	if len(lists) == 0 {
		return nil
	}
	var dfs func(l, r int) *ListNode
	dfs = func(l, r int) *ListNode {
		if l == r { // 出口
			return lists[l]
		}
		mid := l + (r-l)/2
		return mergeTwoLists(dfs(l, mid), dfs(mid+1, r)) // ← 合并 = 返回
	}
	return dfs(0, len(lists)-1)
}
```

- `148 排序链表`：快慢指针分解（切开成两半）→ 递归 → `mergeTwoLists` 合并
- `226 翻转二叉树`：分解现成，合并 = 前序就地交换
- `94 中序遍历`：无合并，纯粹借框架按顺序收集

## 6. 三种序的选用速查

| 目标 | 用哪一序 |
|---|---|
| 需要子问题结果来算答案（直径、LCA、路径和、最大子树） | 后序 |
| 需要父节点信息影响子节点（BST 上下界、路径目标、剪枝、原地修改） | 前序 |
| 结果顺序依赖左右子树的天然结构（升序、输出中序） | 中序 |
| 只要一个遍历顺序，不汇总 | 任意，能剪枝就选前序 |
